# Правила для AI-ассистентов

Правила для AI-ассистентов, работающих с этим репозиторием.

## Обязательные правила

- Следуйте `Documentation/process/coding-assistants.rst`,
  `Documentation/process/coding-style.rst` и
  `Documentation/process/submitting-patches.rst`.
- Каждый коммит должен содержать `Signed-off-by` (DCO). AI-ассистент не
  подписывает коммит за человека: ответственность и подпись — у автора.
- Указывайте использование AI-ассистента в описании коммита или PR, если оно
  существенно повлияло на код.
- Не добавляйте сгенерированный код без проверки, сборки и тестов. Человек,
  отправляющий изменение, отвечает за его корректность и лицензионную чистоту.
- Не копируйте код из источников с несовместимой лицензией. Сохраняйте SPDX-
  заголовки и существующие лицензионные тексты.
- Не коммитьте секреты, токены, ключи и персональные данные.

## Рабочий процесс

- Изменения ядра — только по явной задаче; не меняйте исходники вне `work/` и
  `.github/workflows/` без необходимости.
- Перед коммитом запускайте доступные проверки из `work/plans/runbook.md`:
  `checkpatch`, `sparse`, `kunit`, `smoke`, а для машинной сборки —
  `build-machine.sh`.
- Коммиты — атомарные, с префиксом подсистемы; документация и код — отдельными
  коммитами, если это возможно.
- Ветки: `dev` — интеграция, `main` — зеркало upstream. Прямые изменения в
  `main` без синхронизации с upstream не допускаются.
